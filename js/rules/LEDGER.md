# The rules ledger

Every export of the old planner's test hook (`window.__GEN2_PLANNER_TEST__`, gen2-planner-main `js/app.js` @ c0a250c,
lines 6837-6855), classified. The approved plan (§1.5) asks for this because policy also hides in render code: a
blocked-reason code, a length gate or a convert plan that lives only in a DOM handler would otherwise be lost when
the old planner is retired.

Classes:

- **moved** · ported by copy into `js/rules/*` (generated by `tools/port-rules.mjs`), behind a parity gate
- **UI-only** · a render, a DOM binding or a planner-page concern; the merged app's workspaces own the equivalent
- **relay** · the planner ↔ viewer / Label Studio relay protocol, retired by the merge (both run in one page)
- **later** · policy the merged app still needs, scheduled for a named phase (not dropped)
- **dropped** · with the reason

## What the parity gates cover

- `test/parity/bom-parity.test.mjs`: `computeBom` on the kits and 120 seeded random builds with option sweeps.
- `test/parity/layout-parity.test.mjs`: every **moved** layout predicate on the kits, 120 random builds and broken
  variants of each (a unit removed, a unit shifted, a wall top shrunk), on every mount; the post-state of
  `fixStructure`, `fixWallTops`, `nudgeSelected`, `setMount`; the block reason as the planner renders it; and
  `sanitizeBuild` against the planner's `applyBuild` on each record and four corrupted variants of it.

Not on the hook, so compared indirectly or not at all: `capW`/`capH`/`clampGrid`/`growGridForHeight`
(exercised through `fixStructure` and `fixWallTops`), `fillFits`/`fitProblem`/`maxRailW`/`bedSize` (the kits and
random builds all use printer `any`; the printer path is covered by the planner's own `test/planner.test.mjs`,
which the next weekly bump should port to run against `layout.js`).
