# The stage factory: what it exposes today

Written 2026-10-12, after commit 6021868 (the wrap). This is the honest list, not the target. The target interface is in the approved plan (§1.4: `load`, `update`, `select`, `setColors`, `setMode`, `setSafeArea`, `goTo`, `explode`, `measure`; events `select`, `ready`, `perf`). Each row says whether the wrap delivered it, and what the carve-out still has to do.

## The call

```js
import { createStage } from './js/main.js';
const stage = await createStage(document);
```

| Capability | Today | What is missing |
|---|---|---|
| **Import without side effects** | Yes. `test/stage-import.test.mjs` imports `js/main.js` under node with no DOM and no renderer created; it passed in the 2026-10-12 suite run (459 tests: 451 pass, 6 skipped, 2 pre-existing failures in the EdgeLabel-generator comparisons). | Nothing. |
| **Mount into a container** | No. `container` is accepted and ignored; the body queries `document` by element id (`$('btn-start')`, `getElementById('stage-wrap')`, the canvas) exactly as before, so the stage needs `index.html`'s markup present. | The carve-out replaces the id lookups with lookups scoped to `container`, and the chrome the workspaces take over is removed from the stage's own markup. |
| **Scene-ready** | Partial. The promise resolves after the FIRST `mountManifest` and the render loop start (main.js line 9203 onward), so `await createStage()` is a real "first scene mounted" signal, not a timing guess. | Later mounts (`regenerate()` after an option change, a build swap) signal nothing outward. The plan's `ready(sig)` event after every `mountManifest` is still to add. |
| **Cleanup / dispose** | No. Nothing stops the animation loop, removes the window and document listeners (`load`, `keydown`, `click`, `visibilitychange`, `pointerdown`, the `setInterval` for the paid note) or disposes the renderer. | A `dispose()` that unregisters what the body registers; the carve-out should collect listeners as it moves them. |
| **Multiple instances** | No, and calling the factory twice on one page is unsafe: each call would build its own renderer and both would bind the same element ids and the same window listeners. State is per call (closure), so the limitation is the DOM binding, not shared state. | Follows from mounting into a container plus dispose. |
| **Returned interface** | The object that was the `?debug=1` hook: `THREE`, `scene`, `camera`, `controls`, `goTo`, `applyState`, `instances`, `manifest`, the cinema and confetti controls, `layerHandles`, `bedFinish`, `applyFaceplateStyle` / `FACEPLATE_STYLES`, `applyHandleStyle` / `HANDLE_STYLES`, `seeIntoComponentKeys`, `buildAxisForKey`, `useCustom`, `COLOR_STORE_KEY`, `trackLog`, `track`, and for the screenshot harness `acc`, `ACC_SAMPLES`, `quality`. With `?debug=1` the same object is also installed as `window.__GEN2_VIEWER__`. | This is a debugging surface, not the workspace interface. `manifest` on it is the value at factory return and goes stale after a regenerate. The plan's methods are to be added as thin wrappers over the existing functions (`goTo` already is one). |
| **Loading a different build** | No outward method. The build comes from the URL at boot (`?build=<kit>`, `#build=`, `?kit=`, `?part=`, `?bench=`); changing it means a new page. | `load(build)` / `update(build)` over the existing `applyBuild` + `regenerate` path, with the manifest-hash signature from the plan. |
| **Theme** | The stage reads `gen2-theme` from localStorage and its own toggle button. | `setMode('light'|'dark')` reading the tokens. |
| **Safe area for panels** | Internal: `updateViewInset` already offsets the camera to clear the docked panel. | `setSafeArea(rect)` generalising it to the workspaces' panels. |

## Added for the Build workspace (2026-10-12, same day)

`createStage(document, opts)` now reads two options: `opts.onSelect(sel | null)` fires from `setSelected` with `{ id, node, type, owner, label }`, where `owner` is the unit id of the part or of the drawer it rides (covers, rails, feet and QuickLocks give `null`); `opts.quietSelect` makes a selection highlight only (no drawer glide, no removal ritual, no focus camera), which is Build's rule. The returned object also carries `setSelected`, `build`, `selectedId`, the build-wide option setters the viewer's own panel uses (`setAllClosure`, `setAllStoppers`, `setAllVariant`, `setBackCover`, `setFeet`, `applyFaceplateStyle`, `applyHandleStyle`, `currentFaceplateStyle`, `availableFaceplateStyles`, `currentHandleStyle`), `applyStageTheme` / `stageTheme`, `applyQuality` / `QUALITY` / `quality`, `setDims` / `dimsOn` (the W/H/L callouts), `setMeasure`, `resetView`, `buildSize`. These are thin wrappers over existing functions; mounting, dispose, multiple instances and `load(build)` are unchanged from the table above.

Second pass (Astra's review of the first Build screen, same day): `setSafeArea({ left, right, top, bottom })` takes the px bands the workspace's panels cover; the stage then centres the composition in the free region (`updateViewInset`) and frames whole-build presets to it (`fitDistanceFor`), re-fitting on change unless the user has taken the camera. A quiet select also draws a two-rim outline (white inner, orange outer; an inverted hull of every mesh of the unit) so the selection reads against any filament; it is cleared on deselect and on every rebuild of the instances. The stage gained a `night` theme (the dark stage with a quieter grid and a halved reflection) that only the workspace selects, and exposes the palette: `applyPreset`, `PRESETS`, `activeHex`, `applyPalette`, `useCustom`. Third pass: with a safe area, whole-build presets frame the PROJECTED bounds to 84% of the free region (`fitProjected`, three refinements of the sphere fit), the W/H/L callout labels clamp to the safe area, and `opts.fillBoost` scales the fill light (the shell passes 1.6 so black parts keep their shape). `dims` is readable on the object for harnesses.

Phase 1 (Assemble, same day): `opts.onPage(i)` fires from `goTo` with the new page index (0 the cover, 1 the exploded overview, then the numbered steps, last the outro); the object carries `cur`, `pageCount`, `paused` / `setPaused`, `slowmo` / `setSlow`, `next`, `prev`, `replay`, `skipToEnd`, all driven through the viewer's own buttons so their tracking stays in one place. Workspaces mount and unmount in place (`js/app.js` router): each mount returns `{ onSelect?, onPage?, unmount }`, and the stage is shared across them. Still missing: `load(build)`, dispose, multiple instances, mounting into a container.

## Added for the Build rules (phase 3, 2026-10-14)

`createStage(document, opts)` reads `opts.onContext({ unitId, x, y })` (a right-click or long-press on a unit's part). The returned object carries:

- `update(record, pre?)`: swap the build record and rebuild the scene. The generator judges first (or takes a pre-generated result), so an unshowable layout leaves the last good scene standing and returns `{ ok: false, errors }`; otherwise `regenerate()` runs with that manifest and it returns `{ ok: true }`. Waits out a regenerate already in flight. `manifest` on the object is now a getter, so it follows every rebuild.
- `selectUnit(unitId)`: select a unit by its planner id (the drawer body first, else the shelf insert, case or extender); `unitOf(instanceId)` resolves any instance to its unit, including cases and QuickLocks, which the generator names by the unit's index in its own order (rowIdx, then col) - the stage rebuilds that map per mount. The `onSelect` event's `owner` now uses the same resolution, so a case click selects its unit and the quiet outline wraps every part of it.
- `peekUnit(unitId)` / `unpeek()`: slide a drawer open and closed without the focus camera.
- `unitBox(unitId)`: the world bounds of a unit's visible parts.
- `setSpots({ spots: [{ x, y, w?, hh?, kind? }], w, hh, rows, onPick })`: amber (or red, `kind: 'need'`) translucent boxes with a plus mark at planner cells; hover turns one green; a click calls `onPick(spot)`. `rows` is the caller's grid height in half-rows: heights are placed as half-rows above the mount frame, so the caller's grid may differ from the record's (the store's tabletop grid tracks the build). `spotWorld(spot, w, hh, rows)` is the mapping on its own, taken from a case the scene already holds (88 mm per column, 28 mm per half-row).
- `setFlags([unitIds])`: dashed amber outlines around units (the issue card's).
- `setDrag({ unitId, rows, spots(), onDrop(spot, unitId), onCancel() })`: a pointerdown on that unit lifts a white ghost of it with orbit off; `spots()` (sync or a promise) supplies the valid spots, which appear as the carry starts; the ghost snaps to the nearest spot within 70 px on screen, else rides the camera plane; release on a spot calls `onDrop`. `cancelDrag()` ends a carry without a drop (Escape).
- `setEraser(cb)`: the remove mode - a red box under the cursor, a click hands the unit id to `cb`.

- `thumb({ fill, w, hh, faceStyle?, handleStyle?, handle?, variant?, lip?, view: 'front' | 'three', size? })`: a product-faithful preview. Builds a one-unit tabletop record, runs the generator, loads any part model not yet in the template cache, clones the unit's parts (cases, extenders, drawer, faceplate, accent, label, handle, shelf insert and lips; never covers, rails, feet, QuickLocks or stoppers) with the shared live materials, frames them front-on or three-quarter in an offscreen render target and resolves a PNG data URL. Cached per option set, handle node, plate and palette signature; a failed render is dropped from the cache so it can be retried.

## Added for Colors (phase 4, 2026-10-14)

`createStage(document, { colorStoreKey })` lets the shell key the saved palette per build (default: the viewer's URL-derived key). The object carries `palette()` ({ on, colors, user }, copies), `setColor(key, filament | null)` (one region; the filament is `{ name, hex, url }`), `setPalette({ colors, on, user? })` (the whole working palette), `setUseCustom(on)`, `restoreUserPalette()`, `applyPreset(p)` / `PRESETS` (as before), `keysInBuild()` (every type and Type:zone a mounted part draws, with its part count and whether it is purchased hardware), `partInfo(instanceId)` (label, qty, type, zones, primaryKey, locked, links, owner, ridesDrawer), `setBuildPlate(key)` and `colorLocked(key)`. Every setter saves to the colour store and repaints; none touches history (the workspace commits to the store, whose `extra` snapshots the palette).

Phase 4b adds the per-unit layer: `setOverride(unitId, key, filament | null)`, `clearOverrides(unitId?, key?)`, `overrideFor(unitId, key)`; `palette()` carries `over`; `setPalette({ over })` restores or clears it (a scheme clears it); `keysInBuild()` entries carry `own` (units with their own pick for the key) and `partInfo` carries `own` (this unit's overridden keys); `thumb({ unitId })` renders a unit with its own picks; `setColorStoreKey(key)` moves the saved palette to another key (a build's own).

All overlays live in one `edit-overlays` group outside `instances` (flagged `userData.ghost`), so the BOM, the callouts, measuring, shadows, AO and the reflection never see them. `regenerate(pre)` takes an optional pre-generated result.

## What the goldens do and do not prove

`npm run goldens` proves the picture is unchanged on 60 scenes: 10 official kits × cover / middle step / finished build × Very High / Fast, at 1200×800. It does not cover: the part-preview embed (`?part=`), the planner relay (`?embed=1` driven by the planner), label text on EdgeLabel drawers, the outro scene, light mode, phone widths, or any interaction after the page change. The smoke, profile-lands and relief-tier gates cover the embed route, the filament picker and the quality ladder in a browser; the relay has no automated check here yet.

`setLabels(record)` (phase 5): only the labels changed (the drawers' words and badges, `labelList` / `labelAssign`, `labelStyle`): the fields are copied into the stage's build (`copyLabelFields`) and every label mesh is redrawn in place (`refreshLabelTexts`), with no regenerate and no deselect. The Labels workspace calls it after every label commit and on undo; a layout change still goes through `update()`. The stage reads a drawer's label from the mirror (`unit.label`, `unit.labelBadge`) and a part label's layout or stripe from the list (label-look.js), as the viewer always did.
